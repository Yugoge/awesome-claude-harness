## 要你回答的问题

### 提示词里会问的 6 个（建议一次答完）

1. **P7b：要不要也处理你其他的仓库？** 默认是"只处理 ~/.claude"。这样的话，你其他仓库里 P0 之前装的旧自动推送 hook
   还在：只要提交时 GIT_AUTO_PUSH 不是 0（普通终端、守护进程、P0 之前开的会话），每次提交照样推到远端。"默认不推送"
   在那些仓库就没做到，计划里也没有别的阶段会去掉它们。选"其他仓库也处理"：同样改名停用（可恢复），同样重启跑旧代码的
   fswatch，只报告数量。
2. **P8：三条工具权限规则要不要采用？** 有三个测试期望的权限比现在的策略严（按测试名看：BA 只把观察记进账本、BA
   只能搜索不能抓网页、不同浏览器工具对同一角色等价）。采用就改变 agent 能做什么；不采用就把测试改回符合现在的策略。
   另外最多再问一个只在 root 下才成立的测试情况。
3. **P2：没装 bubblewrap 的机器上，overnight 的 in_place 模式怎么办？** 这种情况下会话还能删掉仓库的 hooksPath
   设置，绕开保护。选项："写进文档当作已知限制"（默认，行为不变）或"启动时直接拒绝 in_place"。
4. **P4：评分怎么问？** (a) 你早上敲 `/close --auto` 一次落地多个任务时：默认每个任务问一次评分（可以跳过，不会卡住）；
   另一个选项是 --auto 时一律不问，只在汇总里列出没评分的。(b) 5 档评分放进 4 个选项：默认"5 完全达成 / 4 小缺口 /
   3 大缺口 / 1-2 未达成（记为 1）"；另一个选项是选了"1-2"再弹一个问题分 2 和 1。
5. **上锁时机（P2 的 G1–G3 和 P5 的 Stop 门共用一个答案）。** 推荐"只管更新之后新开的会话"：已经在跑的会话直到结束都
   不受新门约束，你以前敲过、没做完的命令不会突然被强制做完。另一个选项是"正在跑的会话也立刻管"。P2 只在 Claude Code
   会把新设置推给正在跑的会话时才问；否则直接按推荐做。之后 P5 问一次，P2 已经有答案就不再问。
6. **P6：Claude Code 默认的 general-purpose 子代理，要不要套用策略里那条一直没生效的规则？** 套用后它只能写 docs/dev/
   和临时目录，MCP 工具和 NotebookEdit 会被拒。默认：保持现在的行为。
