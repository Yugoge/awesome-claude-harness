### The gate (hooks/stop-command-gate.py)

Order, cheap checks first:
1. A payload with `agent_id` -> allow.
2. Mode from the coordinator (`off` never reaches the gate).
3. `span = command_span.active_span(transcript)` (P1; TC-4). Only a human-typed harness command outside CONTROL opens
   or replaces a span; every plain prompt continues it; CONTROL, built-in and plugin commands, and records produced by
   the Skill tool, a scheduled task or a wakeup never change it.
4. Time-lock: `lib/overnight.window_open(payload)` (P2) -> block whatever the span, in advisory and block mode, with
   `overnight window open until <end_time>; continue the remaining pipelines` (TC-12).
5. No gated span -> allow.
6. `gaps = todo half + predicate`. Heavy modules load lazily here, inside gated spans only. Any exception becomes the
   gap `gate instrument failure: <type>: <message>` (TC-11).
7. No gaps -> allow. Advisory (until P5-d) -> print `would block` and the gaps on stderr, exit 0. Otherwise exit 2.

**Todo half** (TC-3, TC-14). For a command with a canonical list (scripts/todo/<command>.py, run with the span's
arguments in CLAUDE_TODO_PROMPT), the span's last ok TodoWrite whose item contents equal that list must have every item
completed; a later unrelated list is ignored (run the script through `lib.todo_canonical.run_todo_script`, which P2
made resolve the harness root). /commit, /merge and /push have no canonical list: when the span holds a
TodoWrite list, every item of the last ok call must be completed (Q1 default). When the gate's environment lacks
`CLAUDE_CODE_ENABLE_TODO_TOOLS=1` (pinned in settings.json :21), the todo half is the one gap
`todo tools disabled (CLAUDE_CODE_ENABLE_TODO_TOOLS)`.

artifacts or calling derive_state in the gate, TC-22):
