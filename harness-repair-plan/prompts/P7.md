## Goal

Anyone can clone this repo, run one init, choose optional modules, and get a working harness that is
their own. No tracked file carries the owner's personal values. The owner's machine keeps every personal
setting through an untracked overlay and loses nothing when it pulls this change.

## Owner decisions that govern this phase (from DECISIONS.md)

- **D11** settings.json stays **tracked** in its clean public form. A git clean/smudge filter, declared in
  `.gitattributes` and registered locally by init, strips machine values on commit and restores them on
  checkout. Machine values live in an untracked `settings.machine.json` (gitignored) next to a tracked
  `settings.machine.example.json`. This replaces PLAN-v1's "untrack settings.json" (U1): do not untrack it.
- **D12** Personal values (account names, emails, private paths, the paseo account list, account-suffixed
  model strings, personal tool paths) are never tracked. The owner keeps full support through the overlay.
  Any list of private literals used by a check stays local and untracked.
- **D13** paseo is an **optional module**, off by default, selected at init. With paseo off, nothing paseo
  runs, nothing fails because paseo is absent, and the core harness is complete. Paseo commands and scripts
  stay in the repo for users who enable it. Keep the module mechanism minimal; paseo is the required
  module, add others only where a feature needs machine-specific setup to work.
- **D14** Public permissions = the owner's current local allow list (settings.json) minus personal-path
  entries; curl, wget, docker run, docker exec and package.json edits are allowed, not "ask". Resolve the
  23 entries that differ between settings.json and settings.template.json under this rule. This replaces
  PLAN-v1's U2.
- **D15** No feature retirement; live sessions keep running on this tree.
- **D10** You make pure technical choices yourself and list them in the PR's technical-choices table.

## Requirements

**R1 One settings source.** There must be exactly one hand-maintained settings source. The tracked clean
settings.json is that source; retire settings.template.json (stub or delete per principle 5 if anything
registered reads it at runtime; move every reader: scripts/install/render-settings, scripts/verify-claims.sh

**R2 Filter.** Clean and smudge are inverse and idempotent: `clean(smudge(x)) == x`, and after init
`git status` is clean on both the owner's machine and a fresh machine. Editing the overlay never shows
up as a diff in settings.json. A machine where the filter is not registered must not be able to commit
personal values: pick a producer-side, fail-closed mechanism (D10) and test it.

**R3 Paths.** Nothing tracked hardcodes `/root/.claude` (83 hook commands in settings.json; 23 literals
in 13 code files; PLAN-v1.md section P6 lists the 26 harness-asset lookups of `$HOME/.claude` and 32 runtime-state
paths). Harness assets resolve relative to the install location; runtime state under
`${CLAUDE_CONFIG_DIR:-$HOME/.claude}`. Requirements:
- a fresh clone at `~/.claude` of a non-root user works after init;
- a clone in another directory works after init (document how Claude Code is pointed at it);
- a new session on the owner's machine (root, `/root/.claude`) still works right after pulling this change,
  before any migration step. It must never end up with every tool call blocked because a hook path does
  not resolve (a python hook on a missing file exits 2, which blocks).

**R4 Init.** Extend scripts/bootstrap (or one init entry point it calls) so that one command:
- asks which optional modules to enable (interactive), or takes them from flags for non-interactive use
  (a `--yes`-style default set: paseo off);
- writes `settings.machine.json` if absent, registers the filter in the local git config, and renders or
  re-checks-out settings.json in machine form;
- creates, only if absent: `<home>/logs`, the TMPDIR root, and `~/.config/claude/protected-runtime.json`

Doctor's required checks: every hook path in settings.json exists under this home; the filter round-trip
holds; protected-runtime.json loads with all 10 keys.
