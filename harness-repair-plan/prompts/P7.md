## Goal

Anyone can clone this repo, run one init, choose optional modules, and get a working harness that is their own. No
tracked file carries the owner's personal values. The owner's machine keeps every personal setting through an
untracked overlay and loses nothing when it pulls this change.

## Owner decisions that govern this phase

D# are in DECISIONS.md. S# are the owner clarifications in PLAN-v2.md section 0; they rank right below DECISIONS.md
and above every plan.

- **D11 / S3** settings.json stays **tracked** in its clean public form. A git clean/smudge filter, declared in
  `.gitattributes` and registered locally by init, strips machine values on commit and restores them on checkout.
  Machine values live in an untracked `settings.machine.json` (gitignored) next to a tracked
  `settings.machine.example.json`. Never untrack settings.json (PLAN-v1's U1 is deleted). One hand-maintained
  settings source; settings.template.json is retired or generated. A machine where the filter is not registered must
  not be able to commit personal values (fail closed).
- **S9** The overlay is `<harness>/settings.machine.json` (U3). U4 is resolved by D12: author-specific features stay,
  with their values in the overlay.
- **D12 / S6** Personal values (account names, emails, private project and unit names, personal paths, the paseo
  account list, account-suffixed model strings, personal tool paths) are never tracked; the owner keeps full support
  through the overlay. check-public-core gains a rule driven by a local, untracked private-literal list. It runs
  before a commit lands on an initialised machine and in CI, and is skipped without the list.
- **D13 / S5** paseo is an **optional module**, off by default, chosen at init. With paseo off, nothing paseo runs,
  nothing fails because paseo is absent, and the core harness is complete. Paseo commands and scripts stay in the
  repo for users who enable it. Keep the module mechanism minimal: paseo is the required module; add others only
  where a feature needs machine-specific setup to work.
- **D14 / S4** Public permissions = the owner's current local allow list (settings.json) minus personal-path
  entries; curl, wget, docker run, docker exec and package.json edits are allowed, not "ask" (PLAN-v1's U2 is
  deleted). Resolve the entries that differ between settings.json and settings.template.json under this rule, and
  otherwise pick the strongest coherent posture.
- **D15** Published product: no feature retirement; live sessions keep running on this tree (a registered hook file
  is never deleted in the change that unregisters it).
- **D1** Remote push is opt-in and belongs to P0. A machine that wants remote backup sets `GIT_AUTO_PUSH=1` in its
  overlay.
- **S1 / D4** No Stop-gate work here. `CLAUDE_COMMAND_GATE` does not exist yet (P5 creates it) and tracked settings
  never carry it; because the overlay merges any env key, a human can add it there later.
- **D16 / S7** History rewrite and remote ref deletion are P11's, human-run, after every phase merges. Not yours.
- **D10** You make pure technical choices yourself and list them in the PR's technical-choices table.
- **Producer-side, no agent-writable state.** Every fix lands on its producer: settings.json, the filter, init,
  doctor, the hooks and scripts named below, the git pre-commit hook and CI. Nothing is added to /close, /commit or
  the changelog-analyst. The overlay and the private-literal list are human configuration, not runtime state: only
