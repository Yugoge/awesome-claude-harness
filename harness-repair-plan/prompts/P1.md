## Goal

The three producer gates are G1 (hooks/pretool-obligation-gate.py, at dispatch), G2
(hooks/subagentstop-artifact-contract-enforce.py, at the producer's stop) and G3 (the obligation barrier in
hooks/pretool-aggregate-check.py, at the next dispatch). T1 is the transcript order the CLI really uses: the in-flight
Agent tool_use is already in the transcript when PreToolUse runs. Arm G1-G3 in a sandbox and replay under T1. Every
compliant dispatch and producer stop of /dev, /redev, /dev-command, /do, /close and /commit must then pass, and
disobedient producers must still be stopped. Today arming deadlocks every pipeline except the /do half
(reports/core-architecture-armed-test.md, "Defects that make arming unsafe today"). The shipped settings keep all four
CLAUDE_OBLIGATION_* switches absent, which means advisory; P2 arms G1-G3. Also:

1. dev-report v1 and v2 each have one legal status, `completed` (D2).
2. Every bounded, best-effort or "skipped" exit is gone from the dev prose. The overnight prose parks genuine owner
   decisions instead (S2).
3. A BA or dev producer that needs the owner writes one question artifact,
   `docs/dev/producer-question-<task>-<role>.json`. G2 validates it in place of that dispatch's report. No text line
   skips a file check. The orchestrator relays the question with AskUserQuestion and re-dispatches the same role with a
   fresh dispatched_at (D3, S1). QA fail stays reportable, and QA has no question path.
4. stop-completion-gate is unregistered and becomes an exit-0 stub. Today it blocks every compliant /dev Stop in a
   product repo with GATE_ERROR, armed or not, and its only exit is a self-written arbitration file.
5. The Stop coordinator relays block reasons (today it hashes them away). A crashed, slow or missing phase no longer
   blocks sessions that are not running that phase's command. Where it does block, it names the failure, and the human
   /stop releases it (S1). The coordinator registration gets an explicit timeout.
6. A live capability capture records the CLI facts that P1 and P5 rely on (TC-38).
7. The tool streak and the /do consent flag are cleared at each human prompt, so consent lasts one turn (D5).

Apart from the bug fixes and the removal of a wrongly blocking gate, all of this is behaviour-neutral while the switches
stay advisory.

Put these release notes in the PR (PLAN-v2.md, P1 "Risk and rollback"):
- dev-reports that say blocked or needs_review no longer validate; an in-flight cycle with one needs a dev re-dispatch;
- stop-completion-gate's harness-repo block is gone until P5;

  unaffected;

### Producer question artifact (TC-5)

A ba or dev producer that needs an owner decision writes `docs/dev/producer-question-<task_id>-<role>.json` in place of
its report. Schema producer-question.v1 has these fields:
- `task_id`: the identity; G2 compares it with the obligation's task_id.
- `role`: `ba` or `dev`; G2 compares it with the obligation's role.
- `need`: a string.
- `options`: 2-4 objects `{label, description}`.
- `default`: one of the labels. JSON Schema cannot tie a value to a sibling array's labels, so G2 checks it.
- `why`: a string.

G2 validates it like any artifact (row 2). It never ends a gated command: the cycle stays incomplete until the
re-dispatched role writes its report. P3's disposition will report it as a gap owned by the orchestrator, with the fix
"relay with AskUserQuestion, then re-dispatch <role>". The 2-4 options map one-to-one onto the AskUserQuestion dialog.
Inside an overnight window this artifact is how a subagent asks, so the pipeline can be parked (P2 denies
AskUserQuestion there). A file left over from an earlier round is stale (row 2, case a) and never stands in again.

### Coordinator failure handling (TC-11, TC-39, B3.a, B3.b)
