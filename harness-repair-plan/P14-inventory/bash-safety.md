# Refusal-rule inventory: `hooks/pretool-bash-safety.sh` (master 1ace5ee4, 2,709 lines)

Read-only research lane. Every "pinned by" comes from a search of `hooks/tests/`, `tests/` (incl. `tests/replay/`), `hooks/tests/fixtures/adversarial_corpus.json` / `docs/ADVERSARIAL-CORPUS.md`. Every DEAD or shadow claim comes from a search or from an experiment: the hook was fed synthetic PreToolUse JSON with a throwaway HOME (`scratchpad/home-bs`), an empty `GIT_CONFIG_GLOBAL`, and `CLAUDE_STATE_DIR`/`TMPDIR` in the scratchpad. The runtime guard ran in two modes: (a) no `~/.config/claude/protected-runtime.json`, which is the state of this machine's real home too, and (b) a valid config with every list empty (`CLAUDE_PROTECTED_RUNTIME_FILE`).

## 0. Control flow that decides what "shadowed" means

| Order | Lines | Step | Effect |
|---|---|---|---|
| 0 | 4 | `harness_switch_exit_if_off` | `/harness off` turns off the whole hook (the only switch for BS-01..BS-07) |
| 1 | 108-134 | four inline `python -c` JSON reads (IS_SUBAGENT, TOOL_NAME, COMMAND) + views | |
| 2 | 136-307 | BS-01..BS-03 | before any bypass |
| 3 | 310-413 | BS-04..BS-07 commit guard | before any bypass, "every caller" |
| 4 | 786-791 | **main-agent `/do` consent -> `exit 0`** (through the BS-08 pre-clean guard) | releases EVERY later rule |
| 5 | 806-833 | **structured `/allow` sentinel grant -> allow JSON + `exit 0`** (through BS-08), subagents too | releases EVERY later rule |
| 6 | 835-2707 | BS-09..BS-45 | bypassable by step 4/5 |

Experiment: with a live `/do` consent flag, `cat session_dirs.txt`, `echo {} > <state>/claude-commit-grant-x-y.json` and `git push --force origin master` all exit 0 from this hook, even though their messages say "PERMANENTLY FORBIDDEN". `git commit --no-verify` still exits 2.

PreToolUse hooks run in parallel (`settings.json`: `pretool-launch.py` runs `pretool-git-privilege-guard.py`, `pretool-block-branch-pr-worktree.py`, the write gate (`pretool-tool-policy.py`, `pretool-overnight-hook-guard.py`, ...), and so on, beside this file). So "shadowed by another hook" here means that a parallel hook that is always on refuses a superset, which makes this rule redundant for the combined decision. It does not mean "never evaluated". `settings.json` `permissions.deny` also holds prefix rules that overlap some rules here (`Bash(*session_dirs.txt*)`, `Bash(dd:*)`, `Bash(mkfs:*)`, `Bash(fdisk:*)`, `Bash(git push --force:*)`, `Bash(git push -f:*)`, `Bash(git reset --hard:*)`, `Bash(systemctl restart|stop|disable|enable|reload|kill|try-restart|reload-or-restart:*)`).

CLS = `hooks/lib/git_command_classifier.py` JSON (stripped view plus the raw view after a NUL, nested `-c` resolution), re-read by its own inline `python -c`. ONE = `COMMAND_ONE_LINE` (newlines become spaces).
