# Git-guard refusal inventory (master 1ace5ee4)

Scope: every refusal path (exit 2 / DENY) on the Bash path of `hooks/pretool-git-privilege-guard.py` (GP),
`hooks/lib/git_command_classifier.py` (GC) and `hooks/lib/git_clean_guard.py` (GCL).
Method: full read of the three files, greps over `hooks/tests`, `tests/`, `docs/ADVERSARIAL-CORPUS.md`,
`hooks/tests/fixtures/adversarial_corpus.json`, `tests/replay/`, plus experiments: JSON payloads on stdin with
`HOME=<scratch>/home-gp` (repo linked as `$HOME/.claude`), `GIT_CONFIG_GLOBAL=<scratch>/home-gp/gitconfig` (empty),
`GIT_CONFIG_NOSYSTEM=1`, `CLAUDE_STATE_DIR=<scratch>/home-gp/state`, `env -i`, throwaway repo `<scratch>/home-gp/repo`
(branch master, `refs/remotes/origin/HEAD -> origin/master`). Runner: `<scratch>/bin/run.sh`.

Class legend: KEEP-LOCAL (protects local tree/refs/harness or is parser/fail-closed infra), MERGE (duplicate of a
bash-safety / tool-policy rule, named), GITHUB (only protects the remote; replaceable by branch protection/rulesets),
DEAD (unreachable in production, evidence given).

Common switches for all GP rules: `/harness off` (`hooks/lib/harness_switch.py`, guard lines 165-172) disables the
whole hook; no `CLAUDE_*` env switch exists in the guard. `/allow` = sentinel grant via
`lib.allowlist.match_sentinel_grant_for_bash_command` (`_check_git_allowlist`, :388-400; fast path :2075 for every
non-push command). `/do` = `has_do_consent` (main agent only), releases GP-04/05/06/14 only (`_DO_RELEASED`, :1831).

## 2. lib/git_command_classifier.py (GC)

The library emits no exit code itself. It decides refusals in two ways: (a) `residuals` from `classify_git_command`
(:1835-1858), consumed ONLY by GP-02 (grep: no other caller of `classify_git_command`/`_residual_shapes`); (b) the
invocation list, consumed by GP, by `pretool-bash-safety.sh` (CLI mode, `CLASSIFIER_PY` :1195, JSON for reset-hard,
force-push, ref mutation, stash, revert/cherry-pick/rebase), by R7b (`_command_token_index`, `_git_subcommand` at
bash-safety :326), `pretool-block-branch-pr-worktree.py:279`, `pretool-bulk-commit-detector.py:44`,
`pretool-tool-policy.py:235` (`iter_shell_texts`), and only its option table by `pretool-overnight-hook-guard.py:41`,
`lib/runtime_guard/git_cmds.py:37`, `git_clean_guard.py`, `lib/allowlist.py:344`.

Reading mechanisms (own, no shlex): `_segments_with_kind` (:138-256, quote-blind char splitter on `; \n | & && || ( ) $( <( >( \``,
passive quote tracking), `str.split()` per segment, `_command_token_index` (:345-405), `_git_subcommand` (:439-450);
for `-c` layers a second, quote-aware lexer `_shell_words`/`_expansion`/`_skip_*` (:805-1087) and here-doc expansion
(:1109-1160). Two lexers inside one library.

## 4. Open items

1. `git -c x=y commit -m "fix(session-recovery)"`. Not in any of the three files: GP refuses it only as an ungranted commit (GP-30). The hard-ban refusal is `pretool-bash-safety.sh:1644-1681` ("hard-banned scripts", default `session-recovery|restart-all-sessions`). Mechanism: the match uses `_HB_CMD` (:1648), where `(` counts as a command start; quoted data is masked by `_HB_MASK` (:1649-1672) UNLESS the unquoted text holds a "may run text" word, regex `r` (:1671) which includes `-\w*[ce]\w*` ("a -c/-e option"). `git -c` matches that alternative, so masking is abandoned (prints raw text), and `(session-recovery` inside the message matches. Experiment: `git -c x=y commit -m "fix(session-recovery)"` -> BS rc=2 "hard-banned script 'session-recovery'"; without `-c` rc=0; `git -c x=y commit -m "fix: session-recovery"` rc=0. `hooks/tests/test_env_configured_defaults.py:152` pins the no-`-c` form as allowed; no test covers the `-c` form either way. Same class in GP via GC-09: `git -c a=b commit -m "x; git push origin"` is refused as a push (exp.), because `_is_text_only` (:1810-1813) stops treating a commit's quoted text as text once `-c`/`--config-env` appears.

## 5. Other findings (experiments)

- F1 Pipe/here-string to a shell is invisible to GC, GP and BS: `echo "git push --force origin master" | sh`, `echo "git reset --hard HEAD~1" | sh` -> GP rc=0, BS rc=0; classifier returns `([], [])` also for `sh <<< "git push --force"`, `printf "git push -f\n" | bash`. Only a quoted string containing a separator (`"x; git push"`) is caught (GC-09).
- F2 `python3 -c "import os; os.system(\"git push --force origin master\")"` -> GP/BS rc=0 (no separator before `git`); the iter_git_invocations docstring claims interpreters fail closed.
- F3 Trailing-quote token quirk: an in-quote invocation keeps the closing quote on its last word, so `python3 -c "x; git reset --hard"` -> subcommand args `['--hard"']` -> GP rc=0, while `... --hard HEAD~1"` -> rc=2; `python3 -c "x; git push"` yields subcommand `push"`.
- F4 Over-blocks from GC-09: `echo "x; git push origin" | cat` refused as a push; `git -c a=b commit -m "x; git push origin"` refused as a push.
- F5 Abbreviated options pass both GP and BS: `git reset --har HEAD~1`, `git branch --del feat`; force set misses `-uf`, `--force-if-includes`, `--prune` (masked today by GP-09 default deny, relevant under /allow).
