## 3. Principles

- **Producer-side only (design doc C2).** Every fix lands on the single producer of its artifact: a hook, the launcher, the UserPromptSubmit hook, a producer prompt, the resolver, the renderer or CI. One function computes the disposition for every stage. /close, /commit and the Stop gate consume it and never re-validate, re-derive or add a check. When the disposition is incomplete, they dispatch again, under the same task id, the dispatch that declared each missing or invalid artifact. No table maps file names to roles (D21). /close and /commit only shrink.
- **One producer per artifact; consumers trust one conclusion (D24).** Each phase states, for every artifact it touches, its producers and its deciding consumers before and after, measured by grep and a sandbox write trace. An artifact without a reader, or without a writer, is deleted.
- **Never fail (owner, 2026-10-24; D25).** "还有一件我关心的！就是永远不能失败！每一次开发一定不会在流程上出现任何错误！出现了错误也可以立刻被修复！" A compliant run of any of the ten pipelines (/spec /dev /redev /dev-command /dev-overnight /do /close /commit /merge /push) meets no gate block and no hook error. A fault is stopped at an allowed position (the producer's stop, G1 at dispatch, G3 at collection), its block names the artifact and the failing check, it goes back to that artifact's own producer (read from the dispatch record that declared it, D21), and that producer's next round passes with no human action beyond the owner's own commands (his /restart of a session he interrupted, or of one a usage limit cut outside /dev-overnight, D22, and his /close or /commit that meets an unfinished cycle, D7; inside /dev-overnight a usage-limit cut resumes with none, D20). Apart from the human /stop there is no state in which an agent cannot satisfy a gate. P1c proves this with a CI replay suite on P1b's trace runner; from P1c on every phase merges only with the suite green and adds the fault replay for each process class it changes (section 15).
- **One terminal (D2).** A dev cycle ends only complete: code confirms every lane's BA-QA verdict and QA status are "pass". QA fail or warning, BA needs_clarification and BA-QA fail are process steps that loop back to their producer. Schemas own the legal values; templates carry no required_values.
- **No agent-controlled early exit (D3, D4, S1).** A gated command cannot stop until code confirms its todo list and its artifacts. There is no retry bound, stop_hook_active release, counter, text pause line or self-release token. An agent pauses by asking the owner with AskUserQuestion inside the turn (D23); no Stop occurs and no gate is released. A question must be a real, specific decision the agent cannot make from the request, the code or a sensible default.
- **Waiting happens inside the turn (D23).** A gated command that needs the owner's decision asks with AskUserQuestion and waits for the answer inside the turn. It never loops on blocked Stops on purpose, except inside the overnight window, where the time-lock blocks every Stop by design. There nobody is asked (D20), the PM step plans further work, and /stop is the human control.
- **Exits are human only (S1).** [/stop is D4; the other two exits are planner proposals with no owner quote.] The human-only /stop, any harness command the human types (it replaces the gated span; a command produced by the Skill tool, a scheduled task or a wakeup never does), and CLAUDE_COMMAND_GATE=off in the environment of a session the human starts. Esc interrupts the turn without a Stop (D4c); the next plain prompt resumes the same gated command. An API-error turn runs StopFailure instead of Stop, so it needs no gate code (D4c); Q5 records the owner's view of that CLI behaviour.
- **A broken gate blocks only gated sessions and names itself (S1).** Sessions with no gated command are never blocked by any gate failure. Inside a gated span or an open overnight window, a crash, timeout or missing file blocks with the failure named; /stop releases it. This holds also when the coordinator or stop_contract cannot load, through the import-free launcher. Predicate libraries load only inside gated spans (TC-11).
- **No agent-writable release input (D4).** No file an agent can write decides a release: the overlay, the private-literal list, the CLI transcripts and the /do sidecar are denied to every agent (P5-a), the G2 escalation stores are removed (P1b row 3, P1c row 7; ledger L25), and the /stop helper-auth token and terminal_status are read by no gate (P2). Exits come only from human-typed records and the human-set environment.
- **Hooks are the enforcement primitive; no new mutable state (design C1).** The Stop gate writes nothing. It reads the CLI transcript, the harness code and the project tree, git, its process environment, and one hook-written file (the overnight state); it takes the /do task id from the hook's minted record in the transcript (TC-26). Checklist evidence is the transcript's TodoWrite records.
- **Fix before arm.** P1 fixes every deadlock the armed test found and unregisters the one Stop gate that mis-blocks today. G2 arms in P1b's arming commit (its E4 and Rollback step (7), the last it plans; a later review-fix or merge commit keeps the switch; P1c's X3 arms it only if P1b did not), and G1 and G3 arm in P2. The unified gate ships advisory in P5-b and arms in P5-d, after its predicates exist and the five-sandbox armed replay passes. A predicate added to an armed gate ships warning-only first, then is promoted after the replay (TC-40).
- **Live sessions keep running on this tree (D15).** A running session keeps the hook list it loaded, and python3 on a missing file exits 2. Every unregistered hook stays a tracked exit-0 stub with a STUB marker line (TC-37, D19). Hook paths must keep resolving across P7's settings change.
- **Net-negative in code and rules.** Each phase states a cap on net code lines in hooks/, scripts/ and schemas/ (tests excluded, git diff --numstat). Every PR lists the rules it adds and retires, with retired >= added. Only P1c, P2, P6 and P7's init/install code may be positive.
- **Respect decisions.** D1-D25 are binding, S1-S9 bind below quoted owner words and D20-D25 (section 0), and both override the design doc where they conflict (honest_blocked, forced, bounded anchors, the class-a "cycle failed" outcome, the design's text pause). User-visible semantics are owner decisions, never technical choices. A D10 choice follows the design doc where the doc decides; otherwise it takes the option with less code and fewer rules, gets an armed-sandbox regression test and a choice/why/revert line in its PR.
- **Few edits per file.** settings.json: P0 (:14), P7 (single source), P1 (Stop entry, timeout), P2 (arming), P4 (rating hook), P5 (Stop command = launcher, Stop group, Skill(codex:*) deny), P9 (dead entries). close.md and commit.md: P1, P2, P4, P9 (P7 one docs line). dev.md, dev-command.md, dev-overnight.md: P1, P2, P9 (P8 one redaction line). do.md: P5, P9. merge.md and push.md: P5, P9. redev.md: P9 (P3 leaves it unchanged, D22). Prompt-wording tests change in the same commit as the prose they pin.

## 6. Waves

and merges; a phase session never merges its own PR.

the same files. "Heavy" means a rewrite of a function, a section or more than about 20 lines in one file. Within a
wave, the second PR to merge first merges master into its branch and re-runs its acceptance tests.

**Goal.**
- hooks/stop-command-gate.py, run as the coordinator's completion phase, is the only Stop gate. The registered Stop command is a stdlib launcher, hooks/stop-launch.py (TC-11: no harness import but lib/overnight.window_open, by path, unless a replay makes it copy the rule), that runs the coordinator.
- For /do, /dev, /redev, /dev-command, /dev-overnight, /close, /commit, /merge and /push, a Stop is allowed only when both hold:
  - the todo half: the span's last ok TodoWrite whose items equal the canonical list is complete, or the agent's own last ok list where no canonical list exists (TC-3, TC-14);
  - the command's predicate, computed by the one disposition function or by git, with targets taken from git and the human-typed span opener (TC-25).
- Otherwise it exits 2 with one line per gap. There is no bound, no token and no text pause line; the pause is an in-turn AskUserQuestion (D23), which is not a Stop. The block text tells the agent to finish the gaps and, for a real owner decision, to ask with AskUserQuestion (outside /dev-overnight; inside it the line says to decide without the owner and record it, D20).
- Human exits only (S1): [/stop is D4; the other two exits are planner proposals with no owner quote.] /stop, another human-typed harness command, and CLAUDE_COMMAND_GATE=off in the environment of a session the human starts. Esc interrupts the turn without a Stop (D4c).
- API-error turns: no gate code (D4c). The CLI runs StopFailure instead of Stop on an API error, so the turn ends without the gate; the cycle stays incomplete and /restart resumes it.
- A gate crash, timeout or missing file, including a coordinator or stop_contract that cannot load, blocks inside a gated span or an open overnight window, names the failure and is released by /stop. Ungated sessions are never blocked.
- No agent-writable file releases a gate (D4): the D8 deny covers every caller except the agent whose dispatch obligation declared the path (D21, TC-20); the overlay, the private-literal list, the CLI transcripts and the /do sidecar are denied to every agent, and so is a G2 escalation store only if P1b and P1c left one on the base. **8.2 Findings (H-S1..H-S14).**
1. A rating cannot be recorded in full: replaying close.md Step 3 through pretool-orchestrator-gate gives rc 2 on the 2nd and 3rd user_rating calls (BASH_MAX_CONSECUTIVE=5 at :64; only an Agent dispatch clears the streak, :11-21, :222-239). Without /do consent only ba's row lands.
2. The question uses the obsolete Happy format.
3. The intended behaviour change was never measured: nothing reads the echo fields or compares the log with QA outcomes.
4. Ratings have no dedup and no task check.
5. The tests are dead: CI runs only pytest and bash -n (baseline.yml:124, :137-145); test-lifecycle-cas.sh aborts with rc=5 at :74-75; test-inject-branches.sh needs a venv; tests/generated/INDEX.md lists deleted tests.

The automatic events carry no information: qa_first_pass and qa_second_pass have zero delta; the close_success_* variants share one delta; under D7 close_success_* is a constant +4 per cycle and close_fail_* cannot fire; with no lower bound and -12 for dev per QA rejection, scores saturate at "Disgraced", penalising D2's normal iteration; the injected text threatens irreversible punishment (score-inject.sh:50, :115-119, :187-191).

10. Portability: the path is hard-wired to ${HOME}/.claude; the scripts need a venv, flock and sha256sum; macOS ships no flock.

Assessment: the owner's rating is the only informative signal, and no effect of the injected ranks has ever been measured.

**8.3 D9 design (decided part).**
- The question: /close Step 4 runs after a landed CLOSE: YES* (any suffix) and the temp update. One AskUserQuestion: question "How well did cycle <task-id> meet what you asked for?", header "Rating", multiSelect false, options 5 / 4 / 3 / "1-2" (H-Q3), metadata.source "close-rating:<task-id>". The native dialog adds Skip and free text itself.
- The producer: hooks/posttool-close-rating.py with hooks/lib/close_rating.py is the single writer. It acts only for the main agent and only on an exact label; AFK, decline, deny, free text and Skip write nothing; the first rating per task wins (TC-28); stdlib only; it writes under the existing flock to the existing log (TC-31). The orchestrator never parses or writes (D8), so the Bash cap cannot interfere.
- The Stop gate: the D4 gate requires the question for each task with a landed close-QA YES in the /close span, --auto included (TC-27, H-Q5 default). Re-closing an already-closed task with no new close-QA run carries no requirement, and neither does a headless session that cannot offer AskUserQuestion. The gate requires the question asked, not answered (D9b): tool_use plus tool_result, any content.
- S1 consistency: the rating is the final step of a complete cycle, not a question that exits anything. "Asked" is satisfied in one tool call, so it needs no bound and no release token.
- Unattended sessions: --auto is typed by the human (D6a), so it asks once per landed parent. Only overnight and headless sessions are unattended; they never ask and never synthesise a rating. (Overnight sessions never run /close: the human types the landing commands, D6a.)
- Optional guards, only if armed-sandbox measurements show them necessary: model pre-fill of answers (TC-29) and auto-mode classification (TC-30).
