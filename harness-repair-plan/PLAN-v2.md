## 3. Principles

- **Producer-side only (design doc C2).** Every fix lands on the single producer of its artifact: a hook, the launcher, the UserPromptSubmit hook, a producer prompt, the resolver, the renderer or CI. One function computes the disposition for every stage. /close, /commit, continue-cycle.md and the Stop gate consume it and never re-validate, re-derive or add a check. When the disposition is incomplete, they dispatch the producer that owns each gap under the same task id. One owner table, ROLE_BY_ARTIFACT in hooks/lib/obligation.py, names those producers and drives the D8 deny. /close and /commit only shrink.
- **One terminal (D2).** A dev cycle ends only complete: code confirms every lane's BA-QA verdict and QA status are "pass". QA fail or warning, BA needs_clarification and BA-QA fail are process steps that loop back to their producer. Schemas own the legal values; templates carry no required_values.
- **No agent-controlled early exit (D3, D4, S1).** A gated command cannot stop until code confirms its todo list and its artifacts. There is no retry bound, stop_hook_active release, counter, pause line or self-release token. The only way an agent involves the owner is AskUserQuestion, answered inside the turn, so no Stop occurs. A question must be a real, specific decision the agent cannot make from the request, the code or a sensible default.
- **Waiting happens inside the turn (S1, S2).** A gated command that cannot proceed asks with AskUserQuestion, and asks again if the answer does not unblock the work. It never loops on blocked Stops on purpose, except inside the overnight window, where the time-lock blocks every Stop by design (S2); there the PM step plans further work, a pipeline that needs an owner decision is parked, and /stop is the human control.
- **Exits are human only (S1).** The human-only /stop, any harness command the human types (it replaces the gated span; a command produced by the Skill tool, a scheduled task or a wakeup never does), and CLAUDE_COMMAND_GATE=off in the environment of a session the human starts. Esc interrupts the turn without a Stop (D4c); the next plain prompt resumes the same gated command. An API-error turn runs StopFailure instead of Stop, so it needs no gate code (D4c); Q5 records the owner's view of that CLI behaviour.
- **A broken gate blocks only gated sessions and names itself (S1).** Sessions with no gated command are never blocked by any gate failure. Inside a gated span or an open overnight window, a crash, timeout or missing file blocks with the failure named; /stop releases it. This holds also when the coordinator or stop_contract cannot load, through the import-free launcher. Predicate libraries load only inside gated spans (TC-11).
- **No agent-writable release input (D4).** No file an agent can write decides a release: the overlay, the private-literal list, the CLI transcripts, the /do sidecar and the G2 escalation records are denied to every agent (P5-a), and the /stop helper-auth token and terminal_status are read by no gate (P2). Exits come only from human-typed records and the human-set environment.
- **Hooks are the enforcement primitive; no new mutable state (design C1).** The Stop gate writes nothing. It reads the CLI transcript, the harness code and the project tree, git, its process environment, and two hook-written files (the /do task sidecar, which agents cannot write, and the overnight state). Checklist evidence is the transcript's TodoWrite records.
- **Fix before arm.** P1 fixes every deadlock the armed test found and unregisters the one Stop gate that mis-blocks today. G1-G3 arm in P2. The unified gate ships advisory in P5-b and arms in P5-d, after its predicates exist and the five-sandbox armed replay passes. A predicate added to an armed gate ships warning-only first, then is promoted after the replay (TC-40).
- **Live sessions keep running on this tree (D15).** A running session keeps the hook list it loaded, and python3 on a missing file exits 2. Every unregistered hook stays an exit-0 stub, with a STUB marker line, until P10 (TC-37). Hook paths must keep resolving across P7's settings change.
- **Net-negative in code and rules.** Each phase states a cap on net code lines in hooks/, scripts/ and schemas/ (tests excluded, git diff --numstat). Every PR lists the rules it adds and retires, with retired >= added. Only P2, P6 and P7's init/install code may be positive.
- **Respect decisions.** D1-D16 and S1-S9 are binding and override the design doc where they conflict (honest_blocked, forced, bounded anchors, the class-a "cycle failed" outcome, the design's text pause). User-visible semantics are owner decisions, never technical choices. A D10 choice follows the design doc where the doc decides; otherwise it takes the option with less code and fewer rules, gets an armed-sandbox regression test and a choice/why/revert line in its PR.
- **Few edits per file.** settings.json: P0 (:14), P7 (single source), P1 (Stop entry, timeout), P2 (arming), P4 (rating hook), P5 (Stop command = launcher, Stop group, Skill(codex:*) deny), P9 (dead entries). close.md and commit.md: P1, P2, P4, P9 (P7 one docs line). dev.md, dev-command.md, dev-overnight.md: P1, P2, P9 (P8 one redaction line). do.md: P5, P9. merge.md and push.md: P5, P9. redev.md: P3, P9. Prompt-wording tests change in the same commit as the prose they pin.

Steps (each run by the human):
1. **Preconditions** (each author machine; the origin). P0's find command prints nothing. `git ls-remote origin 'refs/backups/claude/*' | wc -l` stays constant across one commit made in a plain terminal. Every phase PR is merged and none is open. No session is running on any home.

4. **Rewrite** (a fresh `git clone --mirror` of origin, outside every home). Keep an offline copy of the pre-rewrite mirror until step 9.
5. **Verify the rewrite** (the mirror). `git log --all --format='%an %ae %cn %ce' | sort -u` shows only public identities. 6. **Delete the 255 remote refs** (origin). `git ls-remote origin 'refs/backups/claude/*' 'refs/checkpoints/*' | awk '{print ":"$2}' | xargs -n 50 git push origin`.
7. **Publish** (origin). Force-push the rewritten branches and tags explicitly (`refs/heads/*`, `refs/tags/*`). Never `--mirror`: GitHub refuses hidden refs such as refs/pull/*.
8. **GitHub purge** (GitHub support), per decision "GitHub purge": request removal of cached views and of pull-request refs that still reach pre-rewrite commits.
9. **Re-clone every clone, live homes included** (D16). In-place re-syncing is not used, because stashes, notes, refs/original, remote-tracking refs and old packs can keep pre-rewrite history. Other clones re-clone the same way. Then delete the offline mirror copy.
