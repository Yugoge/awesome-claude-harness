# demo

The README's three animated heroes are built here. Each hero is an SVG rendered from a trace
manifest (the schema is `manifest.schema.md`), and every line of a manifest names the source its
text came from.

| Hero | Manifest | SVG | Where the lines come from |
|---|---|---|---|
| pipeline | `.github/assets/demo-trace.json` | `.github/assets/pipeline-hero.svg` | composed from a real `/spec` → `/dev` → `/close` → `/commit` → `/push` run, condensed; lines whose source a clean clone lacks cite `.github/assets/pipeline-hero-sources.json` |
| hook | `.github/assets/hook-trace.json` | `.github/assets/hook-hero.svg` | real hook interceptions, condensed |
| guard | `.github/assets/guard-hero.json` | `.github/assets/guard-hero.svg` | a captured run: every line is a byte-exact slice of `.github/assets/hero-capture.txt` |

**Render.** `node tools/demo/gen-svg.mjs <manifest> <out.svg>` writes the SVG. It is
deterministic: the same manifest always gives the same bytes.

**Audit.** `node tools/demo/audit.mjs <manifest> <svg> --strict` checks an SVG against its
manifest: each visible line matches its manifest line, appears in order, and is found in the
source it cites; the SVG is self-contained. Clipping that is accepted is listed, with its reason,
in `known-clipped-ledger.json`; a verdict line can never be listed there.

**Capture (guard hero only).** `scripts/capture-hero-run.py` runs
`examples/guard-demo/run-hero-demo.sh` in a hermetic fixture (a push is refused, allowed once by a
single-use grant, then refused again) and records the real hooks' own output into
`hero-capture.txt`, with `hero-capture-evidence.json` beside it.
`tools/demo/build-hero-manifest.py` turns that capture into `guard-hero.json`, one manifest line
per visible capture line. `tools/demo/normalize-capture.py` replaces only timestamps, absolute
paths, PIDs and temp-dir names, so two captures can be byte-compared.

**Provenance.** `scripts/verify-hero-provenance.py` re-runs the demo, compares the normalized
captures, checks the raw timings and checks that the manifest covers the capture line for line.
`scripts/verify-claims.sh` runs the three strict audits and this provenance check.

`sample-trace.json` and `sample-hook-trace.json` are placeholder manifests for trying the
generator; no hero uses them.
