# README Hero Demo — Capture & Authenticity Contract

> How the animated hero demo of a real `/spec → /dev → /close → /commit → /push` run is captured, and why every line in it is verifiable rather than staged.
> Last updated: 2026-07-14

---

## What the hero demo is

The hero demo is a **deterministically-generated animated SVG**. It is not a screen recording, not a GIF, and not a hand-drawn mock. Every visible line is text lifted from a real pipeline run and replayed with authored motion.

| It **is** | It **is not** |
|-----------|---------------|
| An SVG generated by a pure function from a trace manifest | A screen recording / GIF / video capture |
| Composed from one real `/spec → /dev → /close → /commit → /push` run | A hand-drawn or invented mock |
| Byte-for-byte reproducible from its inputs | A one-off export that cannot be regenerated |
| Machine-auditable against its source manifest | An opaque asset with no provenance |

---

## The authenticity contract

**Every visible line in the demo traces to a real run artifact. The demo is composed from a real run — it is never a screen recording, and no line is invented.**

Concretely, the contract holds when all four conditions are met:

1. **Traceability** — each SVG text node maps to exactly one entry in the trace manifest, and each manifest entry names the real run artifact (log line, report field, commit) it came from.
2. **Determinism** — the SVG is emitted by a pure generator (`tools/demo/gen-svg.mjs`) that takes the manifest as its only content input; same manifest in, same SVG out.
3. **Labeled condensation** — any elision or collapse of the long real run is shown on-screen and counted, never silently hidden.
4. **Auditability** — an audit (`tools/demo/audit.mjs`) enforces that the set of SVG text nodes is a subset of the manifest; an SVG line absent from the manifest fails the audit.

## Capture pipeline

```
real /spec → /dev → /close → /commit → /push run
        │  (harvest visible lines + artifact provenance)
        ▼
.github/assets/demo-trace.json        ← trace manifest (single source of truth)
        │  node tools/demo/gen-svg.mjs (pure, deterministic)
        ▼
.github/assets/<hero>.svg             ← animated SVG (motion/layout authored)
        │  node tools/demo/audit.mjs   (text nodes ⊆ manifest)
        ▼
audit passes → safe to embed in README
```

| Stage | Artifact | Role |
|-------|----------|------|
| Run | pipeline logs + `*-report.json` + commits | The real events the demo depicts |
| Manifest | `.github/assets/demo-trace.json` | Single source of truth; one entry per visible line, each with provenance back to the run |
| Generate | `tools/demo/gen-svg.mjs` | Pure deterministic generator: manifest → animated SVG |
| Audit | `tools/demo/audit.mjs` | Enforces every SVG text node is present in the manifest |

## The trace manifest is machine-checkable

`.github/assets/demo-trace.json` is the **single source of truth** for the demo's text. Each entry pairs the exact string shown on-screen with a pointer to the real run artifact it came from — a log line, a report field, or a commit — so a reviewer can follow any visible line back to the run without trusting the author.

Because the generator reads only the manifest for content, the audit can assert set membership: the manifest is the whitelist, and any SVG line outside it is a defect. Provenance is data, not narration — it lives in the manifest, checked by a program.

---

## Condensation is labeled and counted

A real run is long; the hero demo is short. Every place the demo shortens the run is marked on-screen and quantified, so the viewer always knows what was collapsed and by how much.

| Real run | In the demo | On-screen label |
|----------|-------------|-----------------|
| 4 subagents dispatched | Collapsed to one line | `… 4 subagents …` |
| N elided log lines | Collapsed | `… N lines …` |

No line is dropped silently. Condensation is a visible, counted transformation — never a hidden one.

---

## Provenance surfaces

The proof is shown in two places; neither invents facts beyond the manifest.

| Surface | Location | Content |
|---------|----------|---------|
| In-SVG footer | Baked into the generated SVG | **Claims only** — states that the demo is composed from a real run and points at the manifest |
| README caption | `README.md`, under the hero image | Human-readable line that **links the manifest** so a reader can open and verify it |

The footer and the caption use the **same provenance vocabulary** ("composed from a real run"), so a reader crossing from the README into the manifest sees consistent terms.

## Regenerate and re-audit

```bash
# Regenerate the SVG from the trace manifest (deterministic)
node tools/demo/gen-svg.mjs

# Audit: every SVG text node must be present in the manifest
node tools/demo/audit.mjs
```

A clean audit is the gate for embedding the SVG in the README. If the audit fails, the SVG contains a line that is not backed by the manifest — fix the manifest or the generator, never the audit.

## Authored vs real

The aesthetic is designed; the words are not.

| Authored (design choices) | Real (from the run) |
|---------------------------|---------------------|
| Motion, timing, pacing | All textual content of every line |
| Layout and framing | Command names, log lines, report fields |
| Paper aesthetic, color, type | Ordering and structure of the run |
| Which lines to condense (labeled + counted) | The lines themselves and their provenance |

**Rule:** anything a viewer can *read* comes from the real run and is checked against `.github/assets/demo-trace.json`. Everything else — how it looks and moves — is authored.
