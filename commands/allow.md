(An /allow grant is the owner's one-time release of the next call the harness refuses, and only the owner types it: `disable-model-invocation: true` and the `Skill(allow)` entry of the deny list (`policies/cli-deny.v1.json`, refused by `hooks/pretool-deny-list.py`) keep the model from invoking it. When the owner types it, `hooks/userprompt-consent-allowlist.sh` writes the grant and prints a notice saying whether it is open or restricted to a tool or command; the pre-tool launcher releases and spends it (`hooks/lib/hook_launch.py` release_refused; grant mechanics: `hooks/lib/allowlist.py`); the body asks nothing of the model. It stays non-empty because a command whose body is empty fails the API call with a 400.)
